Как получить Union_Insp.Insp_Code для факультета (NewStud)

Этот гид описывает устойчивый способ получить инспектора (Union_Insp.Insp_Code), связанного с наборами факультета через Plan_Year_Enter.FK_Insp, только если у набора есть активные студенты. Инспектор это пользователь АИС Студент, в таблице Union_Insp хранятся его логин и пароль для входа в систему. Под «живыми» понимаются студенты, у которых последний статус в Status входит в набор: 1, 2, 3, 4, 5, 9.

Используется Microsoft SQL Server. Запросы ориентированы на схему БД NewStud.

1) Термины и ключевые таблицы

  • Факультет — Firm, где FK_Type_Firm = 3. Идентификатор: Firm.NFirm.
  • Набор — Plan_Year_Enter, привязка к инспектору через FK_Insp (код из Union_Insp.Insp_Code).
  • Группа — Group_Stud, связана с набором через FK_Plan_Year.
  • Студент — Entrant, связь с группой по (FK_Group_Stud, Owner_Group, NFirm).
  • Статусы студента — Status. Нужен последний по дате/ключу.
  • Инспектор — Union_Insp, поле Insp_Code.

Активные статусы: 1 (зачислен), 2 (восстановлен), 3 (вернулся), 4 (переведен на курс ниже), 5 (переведен на следующий курс), 9 (допущен к ИГА).

2) Как получить NFirm факультета (пример для мехмата)

Если вы не уверены в идентификаторе факультета:

SELECT Nfirm, Firm_Name
FROM dbo.Firm
WHERE FK_Type_Firm = 3  -- факультеты
  AND Firm_Name LIKE N'%механико-математичес%';
-- Часто мехмат = NFirm = 1

3) Разовый запрос: инспектора с «живыми» студентами по факультету

Запрос ищет инспекторов для факультета @Nfirm, у которых по привязанным наборам есть активные студенты (по последнему статусу). 

DECLARE @Nfirm INT = 1;  -- мехмат

;WITH LastStatus AS (
    SELECT s.FK_Entrant,
           s.FK_Status_Type,
           ROW_NUMBER() OVER (
               PARTITION BY s.FK_Entrant
               ORDER BY s.Status_Date DESC, s.PrK_Status DESC
           ) AS rn
    FROM dbo.Status s
    WHERE s.NFirm = @Nfirm
),
ActiveEntrants AS (
    SELECT e.PrK_Entrant,
           pye.FK_Insp
    FROM dbo.Plan_Year_Enter pye
    JOIN dbo.Group_Stud gs
      ON gs.NFirm = pye.NFirm
     AND gs.FK_Plan_Year = pye.PrK_Plan_Year
    JOIN dbo.Entrant e
      ON e.NFirm = gs.NFirm
     AND e.FK_Group_Stud = gs.PrK_Group_Stud
     AND e.Owner_Group  = gs.Owner
    JOIN LastStatus ls
      ON ls.FK_Entrant = e.PrK_Entrant
     AND ls.rn = 1
     AND ls.FK_Status_Type IN (1,2,3,4,5,9)  -- активные/обучающиеся
    WHERE pye.NFirm = @Nfirm
)
SELECT ui.Insp_Code,
       ui.Union_Name,
       COUNT(DISTINCT ae.PrK_Entrant) AS ActiveStudents
FROM ActiveEntrants ae
JOIN dbo.Union_Insp ui
  ON ui.Insp_Code = ae.FK_Insp
GROUP BY ui.Insp_Code, ui.Union_Name
ORDER BY ActiveStudents DESC, ui.Union_Name;

Результат: список инспекторов и количество «живых» студентов, привязанных к их наборам внутри факультета.

4) Обернуть в хранимую процедуру

Процедура с опциональной фильтрацией по году набора @Year_Enter:

CREATE OR ALTER PROC dbo.am_GetInspectorsWithActiveStudents
    @Nfirm INT,
    @Year_Enter INT = NULL   -- опционально: ограничить конкретным набором
AS
BEGIN
    SET NOCOUNT ON;

    ;WITH LastStatus AS (
        SELECT s.FK_Entrant,
               s.FK_Status_Type,
               ROW_NUMBER() OVER (
                   PARTITION BY s.FK_Entrant
                   ORDER BY s.Status_Date DESC, s.PrK_Status DESC
               ) AS rn
        FROM dbo.Status s
        WHERE s.NFirm = @Nfirm
    ),
    ActiveEntrants AS (
        SELECT e.PrK_Entrant,
               pye.FK_Insp
        FROM dbo.Plan_Year_Enter pye
        JOIN dbo.Group_Stud gs
          ON gs.NFirm = pye.NFirm
         AND gs.FK_Plan_Year = pye.PrK_Plan_Year
        JOIN dbo.Entrant e
          ON e.NFirm = gs.NFirm
         AND e.FK_Group_Stud = gs.PrK_Group_Stud
         AND e.Owner_Group  = gs.Owner
        JOIN LastStatus ls
          ON ls.FK_Entrant = e.PrK_Entrant
         AND ls.rn = 1
         AND ls.FK_Status_Type IN (1,2,3,4,5,9)
        WHERE pye.NFirm = @Nfirm
          AND (@Year_Enter IS NULL OR pye.Year_Enter = @Year_Enter)
    )
    SELECT ui.Insp_Code,
           ui.Union_Name,
           COUNT(DISTINCT ae.PrK_Entrant) AS ActiveStudents
    FROM ActiveEntrants ae
    JOIN dbo.Union_Insp ui
      ON ui.Insp_Code = ae.FK_Insp
    GROUP BY ui.Insp_Code, ui.Union_Name
    ORDER BY ActiveStudents DESC, ui.Union_Name;
END
GO

-- Примеры вызова:
EXEC dbo.am_GetInspectorsWithActiveStudents @Nfirm = 1;               -- все наборы
EXEC dbo.am_GetInspectorsWithActiveStudents @Nfirm = 1, @Year_Enter = 2025;  -- только набор 2025

5) Почему фильтр через Plan_Year_Enter корректен

  • Привязка инспектора идёт через набор (Plan_Year_Enter.FK_Insp), а не напрямую к факультету.
  • Студенты связаны с набором через Plan_Year_Enter → Group_Stud (FK_Plan_Year) → Entrant.
  • Поэтому «инспектора с живыми студентами» корректно считать через цепочку Plan_Year_Enter → Group_Stud → Entrant → Status.

6) Тонкости и крайние случаи

  • Общие группы: если Group_Stud.FK_Sub_Plan = NULL, запрос всё равно корректно учитывает студентов (связь идёт через FK_Plan_Year).
  • Множественные наборы: процедура позволяет ограничить расчёт конкретным @Year_Enter.
  • Последний статус: используется ROW_NUMBER() по Status_Date и (на всякий случай) PrK_Status.
  • Нормализация статусов: убедитесь, что набор активных кодов соответствует вашей локальной политике.

7) Производительность

Индексы, которые стоит проверить/добавить:

  • Status(FK_Entrant, NFirm, Status_Date DESC, PrK_Status DESC) — покрытие для CTE LastStatus.
  • Group_Stud(NFirm, FK_Plan_Year) и Group_Stud(NFirm, PrK_Group_Stud, Owner).
  • Entrant(NFirm, FK_Group_Stud, Owner_Group).
  • Plan_Year_Enter(NFirm, PrK_Plan_Year) и Plan_Year_Enter(NFirm, Year_Enter) при частых фильтрах по году.

Если объёмы большие, можно материализовать «последний статус» в отдельной таблице и обновлять инкрементально.

8) Быстрая проверка «на глаз»

Чтобы прикинуть, есть ли активные студенты у факультета по наборам, сделайте агрегацию по Year_Enter:

DECLARE @Nfirm INT = 1;

;WITH LastStatus AS (
    SELECT s.FK_Entrant,
           s.FK_Status_Type,
           ROW_NUMBER() OVER (
               PARTITION BY s.FK_Entrant
               ORDER BY s.Status_Date DESC, s.PrK_Status DESC
           ) AS rn
    FROM dbo.Status s
    WHERE s.NFirm = @Nfirm
)
SELECT pye.Year_Enter,
       COUNT(DISTINCT e.PrK_Entrant) AS ActiveStudents
FROM dbo.Plan_Year_Enter pye
JOIN dbo.Group_Stud gs
  ON gs.NFirm = pye.NFirm
 AND gs.FK_Plan_Year = pye.PrK_Plan_Year
JOIN dbo.Entrant e
  ON e.NFirm = gs.NFirm
 AND e.FK_Group_Stud = gs.PrK_Group_Stud
 AND e.Owner_Group  = gs.Owner
JOIN LastStatus ls
  ON ls.FK_Entrant = e.PrK_Entrant
 AND ls.rn = 1
 AND ls.FK_Status_Type IN (1,2,3,4,5,9)
WHERE pye.NFirm = @Nfirm
GROUP BY pye.Year_Enter
ORDER BY pye.Year_Enter DESC;

Так вы быстро увидите, по каким наборам есть активные студенты, до того как искать конкретных инспекторов.

Контакты и контекст

Фрагмент предназначен для использования в RAG‑агентах (n8n/LLM) как «знаниевая карточка» по поиску инспектора/инспекторов с «живыми» студентами для заданного факультета в БД NewStud.
