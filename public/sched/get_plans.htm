Этот документ содержит два «копипастных» T‑SQL запроса по схеме NewStud и краткое объяснение логики, чтобы RAG-агент стабильно отвечал на вопросы про факультеты и учебные планы.

Контекст и ключевые таблицы

  • Firm — справочник организаций (факультеты/институты и т.п.). Частый фильтр для факультетов МГУ: FK_Type_Firm = 3 и NFirm_Parent = 99.
  • Educ_Plan — учебные планы (PrK_Plan, Nfirm, Fk_Type, Fk_Form_Educ и т.п.).
  • Plan_Year_Enter — связь плана с годом набора (Year_Enter).
  • Subject_Name_Order — дисциплины в плане.
  • Comp_Term — компоненты семестра (Num_Term, Beg_Act, End_Act и нагрузки).
  • Type_Business — уровень/тип обучения (PrK_Type).
  • Form_Education — форма обучения (PrK_Form_Educ).

Маппинг учебного года и семестра

  • Course = (Num_Term + 1) / 2 (целочисленно).
  • Year_Enter = Year_Study - (Course - 1).
  • Проверка валидности Comp_Term для нужного набора: ct.Beg_Act <= Year_Enter AND (ct.End_Act = 0 OR ct.End_Act >= Year_Enter).

Запрос 1: список факультетов (МГУ)

Возвращает список факультетов с полезными полями для UI/вывода.

SELECT
    f.NFirm,                 -- faculty id
    f.Firm_Name,            -- full name
    f.Short_Name,           -- short name
    f.Name_Gen_Case,        -- genitive case (for Russian UIs)
    f.Engl_Name_Firm        -- English name (if filled)
FROM dbo.Firm AS f
WHERE f.FK_Type_Firm = 3     -- faculty
  AND f.NFirm_Parent = 99    -- MSU root org (adjust if needed)
ORDER BY f.Firm_Name;

Подсказка: если нужно ограничить конкретным факультетом, добавьте AND f.NFirm = @Nfirm.

Запрос 2: учебные планы по факультету/году/семестру

Запрос возвращает планы, которые реально «живые» для заданных @Year_Study и @Num_Term. Ключевая идея — EXISTS по Comp_Term для проверки, что в этом семестре есть компоненты для нужного набора. 

/* Parameters */
DECLARE @Nfirm        INT  = 3;     -- faculty (Firm.NFirm)
DECLARE @Year_Study   INT  = 2025;  -- academic year start (2025 => 2025/26)
DECLARE @Num_Term     INT  = 1;     -- plan term: 1..12 (13 = non-teaching, usually)
DECLARE @Fk_Form_Educ INT  = 1;     -- Form_Education.PrK_Form_Educ (1 = очная)
DECLARE @Fk_Type      INT  = 1;     -- Type_Business.PrK_Type (1 = основное отделение/бакалавриат)

IF @Num_Term NOT BETWEEN 1 AND 12
BEGIN
    RAISERROR (N'@Num_Term must be in 1..12.', 16, 1);
    RETURN;
END;

-- Map term to course and entrance year
DECLARE @Course     INT = (@Num_Term + 1) / 2;       -- 1..6
DECLARE @Year_Enter INT = @Year_Study - (@Course - 1);

SELECT DISTINCT
    ep.PrK_Plan                    AS Plan_ID,
    ep.Name_Plan                   AS Plan_Name,
    ep.Nfirm,
    ep.Fk_Type,
    tb.Name_Type                   AS Type_Name,       -- human-readable
    ep.Fk_Form_Educ,
    fe.Name_Form_Educ              AS Form_Name,       -- human-readable
    ep.God,
    ep.Engl_Name_Plan              AS Engl_Plan,
    @Course                        AS Course,          -- derived from @Num_Term
    @Year_Enter                    AS Year_Enter       -- derived from @Year_Study & term
FROM dbo.Educ_Plan ep
JOIN dbo.Plan_Year_Enter pye
  ON pye.FK_Plan = ep.PrK_Plan
 AND pye.Nfirm   = ep.Nfirm
JOIN dbo.Type_Business tb
  ON tb.PrK_Type = ep.Fk_Type
JOIN dbo.Form_Education fe
  ON fe.PrK_Form_Educ = ep.Fk_Form_Educ
WHERE ep.Nfirm        = @Nfirm
  AND pye.Year_Enter  = @Year_Enter
  AND ep.Fk_Form_Educ = @Fk_Form_Educ
  AND ep.Fk_Type      = @Fk_Type
  AND EXISTS (
        SELECT 1
        FROM dbo.Subject_Name_Order sno
        JOIN dbo.Comp_Term ct
          ON ct.NFirm      = sno.NFirm
         AND ct.CodOrderID = sno.PrK_Subject_Order
        WHERE sno.FK_Plan = ep.PrK_Plan
          AND sno.NFirm  = ep.Nfirm
          AND ct.Num_Term = @Num_Term
          AND ct.Beg_Act <= @Year_Enter
          AND (ct.End_Act = 0 OR ct.End_Act >= @Year_Enter)
          -- Optional: exclude technical/externals if used in your instance
          -- AND (sno.Sup_Property IS NULL OR sno.Sup_Property <> 55)
          -- AND ISNULL(ct.FK_Sub_Plan, 0) <> 0  -- if you want only subplan-specific components
    )
ORDER BY ep.Name_Plan;

Зачем тут EXISTS?

Он гарантирует, что у плана есть реальные компоненты в Comp_Term для нужного семестра и набора, а не только формальная запись.

Как подстроить фильтры

  • Уровень/тип: меняйте @Fk_Type по Type_Business (например, магистратура/специалитет).
  • Форма: меняйте @Fk_Form_Educ по Form_Education (очная/заочная/вечерняя и т.п.).
  • Технические компоненты: можно включить исключения по Sup_Property, если у вас это используется.

Справочник полей

  • Firm(FK_Type_Firm, NFirm_Parent) — иерархия/фильтрация факультетов.
  • Educ_Plan(PrK_Plan, Nfirm, Fk_Type, Fk_Form_Educ, God) — свойства плана.
  • Plan_Year_Enter(Year_Enter) — год набора (запуск плана).
  • Subject_Name_Order(PrK_Subject_Order, FK_Plan, Nfirm) — дисциплины плана.
  • Comp_Term(CodOrderID, Num_Term, Beg_Act, End_Act) — компоненты и окно валидности.
  • Type_Business(PrK_Type, Name_Type) — человеко-читаемый тип.
  • Form_Education(PrK_Form_Educ, Name_Form_Educ) — человеко-читаемая форма.

Советы для RAG

  • Держите вывод Course и Year_Enter вместе с Num_Term, чтобы не было рассинхрона фильтров.
  • Для скорости часто лучше EXISTS, чем тяжёлые джойны с ранним раздуванием строк.
  • Если нужны нагрузки, расширяйте запрос полями Lect_Load, Sem_Load, Lab_Load, Pract_Load, Quan_Week.
  • Для запросов на уровне групп: дальше обычно идут Sub_Plan → Group_Stud → Entrant и фильтрация по последнему «живому» статусу.
