Документ для RAG-агентов: универсальный запрос для базы NewStud (MS SQL Server), который возвращает список учебных групп и число “активных” студентов при заданных параметрах: NFirm, план, учебный год, курс и семестр.

Назначение

Получить актуальные группы набора для выбранных учебного года и курса, и посчитать по каждой группе количество студентов, чей последний статус является «живым».

Примечание: семестр @Semester обычно не влияет на состав групп, но включён в выдачу как контекст (удобно для трассировки сценариев).

Параметры

  • @Nfirm INT — идентификатор факультета (Firm.NFirm).
  • @PlanID INT — идентификатор учебного плана (Educ_Plan.PrK_Plan).
  • @Year_Study INT — год начала учебного года (например, 2025 для 2025/26).
  • @Course INT — курс обучения (1..N).
  • @Semester INT — семестр (1=осень, 2=весна).

Производные параметры

  • @Year_Enter = @Year_Study - (@Course - 1) — вычисляемый год набора, соответствующий выбранному курсу.
  • @Plan_Year_Enter — запись в Plan_Year_Enter для (@PlanID, @Year_Enter, @Nfirm).

Логика отбора (пошагово)

  • Найти год набора: @Year_Enter = @Year_Study - (@Course - 1).
  • Проверить наличие записи в Plan_Year_Enter по (Nfirm, PlanID, Year_Enter).
  • Выбрать группы из Group_Stud по найденному FK_Plan_Year.
  • Привязать студентов из Entrant к группам по (NFirm, FK_Group_Stud, Owner_Group).
  • Определить последний статус студента через ROW_NUMBER() по убыванию даты/ключа в Status.
  • Оставить «живые» статусы: FK_Status_Type IN (1,2,3,4,5,9).
  • Агрегировать число активных студентов по каждой группе; опционально подтянуть Sub_Plan_Name.

SQL (готов к копированию)

DECLARE 
    @Nfirm      INT        = 1,     -- факультет (Firm.NFirm)
    @PlanID     INT        = 671,   -- Educ_Plan.PrK_Plan
    @Year_Study INT        = 2025,  -- год начала учебного года (например, 2025 для 2025/26)
    @Course     INT        = 1,     -- курс (1..)
    @Semester   INT        = 1;     -- 1=осень, 2=весна (на состав групп напрямую не влияет)

-- Год набора для заданного учебного года и курса
DECLARE @Year_Enter INT = @Year_Study - (@Course - 1);

;WITH PlanYE AS (
    -- Находим запись план↔год_набора
    SELECT pye.PrK_Plan_Year
    FROM dbo.Plan_Year_Enter pye
    WHERE pye.Nfirm = @Nfirm
      AND pye.FK_Plan = @PlanID
      AND pye.Year_Enter = @Year_Enter
),
LatestStatus AS (
    -- Последний статус по каждому студенту
    SELECT 
        s.FK_Entrant,
        s.NFirm,
        s.FK_Status_Type,
        s.Status_Date,
        s.PrK_Status,
        ROW_NUMBER() OVER (
            PARTITION BY s.FK_Entrant
            ORDER BY s.Status_Date DESC, s.PrK_Status DESC
        ) AS rn
    FROM dbo.Status s
),
ActiveEntrants AS (
    -- Оставляем только «живые» статусы (учится/активен): 1,2,3,4,5,9
    SELECT ls.FK_Entrant
    FROM LatestStatus ls
    WHERE ls.rn = 1
      AND ls.FK_Status_Type IN (1,2,3,4,5,9)
),
GroupsOnPlanYear AS (
    -- Группы для найденного план-год-набора (учебные группы текущего набора)
    SELECT 
        gs.Nfirm,
        gs.PrK_Group_Stud,
        gs.Owner,
        gs.FK_Sub_Plan,
        gs.FK_Plan_Year,
        gs.Group_Name
    FROM dbo.Group_Stud gs
    JOIN PlanYE pye
      ON pye.PrK_Plan_Year = gs.FK_Plan_Year
    WHERE gs.Nfirm = @Nfirm
)
SELECT 
    g.Nfirm,
    @PlanID                          AS Plan_ID,
    @Year_Study                      AS Year_Study,
    @Course                          AS Course,
    @Semester                        AS Semester,
    g.FK_Plan_Year                   AS Plan_Year_Enter_ID,
    g.PrK_Group_Stud                 AS Group_ID,
    g.Group_Name,
    g.FK_Sub_Plan,
    sp.Sub_Plan_Name,
    COUNT(e.PrK_Entrant)             AS Student_Count
FROM GroupsOnPlanYear g
LEFT JOIN dbo.Sub_Plan sp
       ON sp.PrK_Sub_Plan = g.FK_Sub_Plan
      AND sp.Nfirm        = g.Nfirm
LEFT JOIN dbo.Entrant e
       ON e.NFirm         = g.Nfirm
      AND e.FK_Group_Stud = g.PrK_Group_Stud
      AND e.Owner_Group   = g.Owner
LEFT JOIN ActiveEntrants ae
       ON ae.FK_Entrant   = e.PrK_Entrant
-- Считаем только тех, чьи последние статусы «живые»
WHERE ae.FK_Entrant IS NOT NULL
GROUP BY 
    g.Nfirm, g.FK_Plan_Year, g.PrK_Group_Stud, g.Group_Name, g.FK_Sub_Plan, sp.Sub_Plan_Name
ORDER BY 
    g.Group_Name;

Требуемые таблицы и ключевые поля

  • Plan_Year_Enter (PrK_Plan_Year, Nfirm, FK_Plan, Year_Enter) — связь плана с годом набора.
  • Group_Stud (Nfirm, PrK_Group_Stud, Owner, FK_Plan_Year, FK_Sub_Plan, Group_Name) — группы набора.
  • Entrant (PrK_Entrant, NFirm, FK_Group_Stud, Owner_Group, ...) — студенты.
  • Status (PrK_Status, FK_Entrant, NFirm, FK_Status_Type, Status_Date, ...) — история статусов.
  • Sub_Plan (PrK_Sub_Plan, Nfirm, Sub_Plan_Name, ...) — подпланы.

Что считается «активным» студентом

В расчёт включаются студенты, у которых последний статус имеет FK_Status_Type в множестве:

  • 1 — зачислен
  • 2 — восстановлен
  • 3 — вернулся после перерыва
  • 4 — переведён на курс ниже
  • 5 — переведён на следующий курс
  • 9 — допущен к ИГА

Статусы 6 (академический отпуск), 7 (отчислен), 8 (окончил) — исключаются.

При необходимости состав «живых» статусов можно параметризовать через таблицу-настройку.

Частые ситуации / отладка

  • Пустой результат: проверьте запись в Plan_Year_Enter для (@Nfirm, @PlanID, @Year_Enter) и наличие групп в Group_Stud по найденному FK_Plan_Year. Убедитесь, что у студентов есть история статусов и последний статус — активный.
  • Группы без подплана: FK_Sub_Plan может быть NULL (общая группа набора). Тогда Sub_Plan_Name тоже будет NULL — это нормально.
  • Семестр: обычно не влияет на состав групп; используется как контекстная метка в выдаче.

Производительность и индексы

  • Status: индекс на (FK_Entrant, Status_Date DESC, PrK_Status DESC) ускорит выбор «последнего статуса».
  • Entrant: индексы по (NFirm, FK_Group_Stud, Owner_Group) и по (PrK_Entrant).
  • Group_Stud: индекс по (FK_Plan_Year, Nfirm).
  • Plan_Year_Enter: индекс по (Nfirm, FK_Plan, Year_Enter).

Варианты расширения

  • Фильтрация по форме обучения/типу (через Educ_Plan) на этапе выбора @PlanID.
  • Настраиваемый набор «живых» статусов (таблица настроек допустимых статусов).
  • Возврат не только количества, но и списка студентов (ФИО, SNILS и т.д.) отдельным запросом/процедурой.

Проверка / пример

Подставьте реальные значения параметров и выполните. Если результат пуст, идите по шагам:

  • Проверьте Plan_Year_Enter по (@Nfirm, @PlanID, @Year_Enter).
  • Посмотрите группы в Group_Stud по найденному FK_Plan_Year.
  • Убедитесь, что у студентов есть последний «живой» статус.
