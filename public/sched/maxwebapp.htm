1. Итоги исследования

Платформа MAX предоставляет два ключевых механизма интеграции:

  • Bot API (HTTPS-запросы на platform-api.max.ru) — позволяет боту читать/отправлять сообщения, работать с чатами, получать события через webhook или long polling, прикреплять inline-клавиатуры (в т.ч. кнопку открытия мини-приложения).
  • Мини-приложение (WebApp) + MAX Bridge — мини-приложение открывается внутри MAX и получает доступ к объекту window.WebApp через подключение max-web-app.js, а также получает стартовые параметры (InitData) с обязательной серверной/клиентской валидацией.

По документированным требованиям MAX ориентирован на работу на широком спектре устройств: для мобильных устройств (iOS/Android) упоминаются экраны от 375px, для компьютеров — рекомендации от 1440px, ограничений на браузеры не заявлено.

Таким образом, MAX можно использовать как «универсальный клиент» для расписания (телефон/планшет/ПК) при условии, что интерфейс мини-приложения адаптивен и сервер валидирует InitData.

2. Возможности MAX API, полезные для приложения расписания

2.1. Сообщения

Получение сообщений и отправка сообщений реализованы через методы раздела messages (GET /messages, POST /messages, также редактирование/удаление). Перечень методов приведён в оглавлении API.

Поддерживается inline-клавиатура (до 210 кнопок) и тип кнопки open_app, которая открывает мини-приложение — это ключевой элемент UX: студенту можно показать сообщение «Открыть расписание» и кнопку.

2.2. Чаты и групповые механики

Для интеграции с групповыми чатами (например, чат группы/потока) важны методы:

  • получить список администраторов группового чата (бот должен быть админом): GET /chats/{chatId}/members/admins.
  • получить закреплённое сообщение: GET /chats/{chatId}/pin.
  • в оглавлении API есть операции закрепления/удаления закрепа и управление участниками/членством.

Практическое применение: закреплять в чате группы кнопку “Открыть расписание” (мини-приложение) либо публиковать ежедневные изменения от бота.

2.3. Подписки и события (webhook / long polling)

MAX рекомендует: Long Polling для разработки и тестирования, Webhook для production.

Указан лимит по запросам к platform-api.max.ru (30 rps).

Практическое применение:

  • получать команды студентов («сегодня», «завтра», «моя группа»);
  • отправлять уведомления об изменениях расписания;
  • собирать подписки на уведомления.

2.4. Загрузка файлов

Метод POST /uploads выдаёт URL для последующей загрузки файла. Также в документации отмечено, что параметр type=photo больше не поддерживается; следует использовать type=image.

Практическое применение: публикация PDF/PNG “расписание недели”, либо выгрузка Excel по запросу.

3. Рекомендуемая модель продукта «Расписание в MAX»

3.1. Компоненты

  • Мини-приложение (WebApp) — основной UI расписания.
  • Бот — канал уведомлений, быстрых команд и «точка входа» в WebApp.

3.2. Роли

  • Студент — просмотр расписания своей группы, подписки, уведомления.
  • Преподаватель — просмотр личного расписания.
  • Администратор (вне MAX, в вашей веб-админке) — управление расписанием.

4. Примеры экранов (UX) для мини-приложения расписания

Ниже — минимальный комплект экранов, который хорошо ложится на ограничения мессенджера и подходит для телефонов/планшетов/ПК.

Экран A. Онбординг / Привязка к группе

  • Вариант 1: студент выбирает факультет → курс → группу.
  • Вариант 2: студент вводит код приглашения/QR от старосты.
  • Кнопка “Готово” сохраняет привязку (user_id MAX → group_id в вашей БД).

Экран B. «Сегодня»

  • Список пар на текущий день: время, предмет, аудитория, преподаватель.
  • Кнопка “Завтра”, “Неделя”.

Экран C. «Неделя»

  • Таблица/карточки по дням недели.
  • Фильтр: “все / только лекции / только лабораторные”.

Экран D. Детали занятия

  • Полная карточка: дата, время, аудитория, преподаватели, тип занятия, комментарий.
  • Если занятие перенесено — показывать исходный и новый слот.

Экран E. Уведомления

  • Настройки: получать изменения по группе, по конкретным предметам, «только отмены/переносы».

5. Примеры кода серверной части (Node.js)

Ниже — примеры, которые соответствуют подходу MAX: bot-интеграция через HTTPS и запуск мини-приложения через кнопку open_app.

Примечание: URL и точные payload полей сообщений/кнопок берите из объектов Message/NewMessageBody в документации, но базовая схема “POST /messages + inline_keyboard/open_app” подтверждена в разделе API.

5.1. Отправка сообщения с кнопкой «Открыть расписание» (open_app)

import fetch from "node-fetch";

const MAX_TOKEN = process.env.MAX_TOKEN;
const API = "https://platform-api.max.ru";

export async function sendOpenApp(chatId, webAppUrl) {
  const body = {
    text: "Расписание доступно в мини-приложении. Нажмите кнопку ниже.",
    attachments: [
      {
        type: "inline_keyboard",
        payload: {
          buttons: [
            [
              {
                type: "open_app",
                text: "Открыть расписание",
                payload: { url: webAppUrl } // фактическая структура зависит от схемы MAX
              }
            ]
          ]
        }
      }
    ]
  };

  const res = await fetch(`${API}/messages`, {
    method: "POST",
    headers: {
      "Authorization": MAX_TOKEN,
      "Content-Type": "application/json"
    },
    body: JSON.stringify(body)
  });

  if (!res.ok) throw new Error(`MAX send failed: ${res.status} ${await res.text()}`);
  return res.json();
}

Ограничения и форматы inline-клавиатуры (включая open_app) описаны в обзоре API.

5.2. Получение обновлений: long polling (для DEV)

export async function pollUpdates(offset) {
  const url = new URL(`${API}/updates`);
  if (offset) url.searchParams.set("offset", String(offset));

  const res = await fetch(url, { headers: { Authorization: MAX_TOKEN } });
  if (!res.ok) throw new Error(`pollUpdates failed: ${res.status}`);

  return res.json(); // ожидаются объекты Update
}

MAX прямо рекомендует long polling для разработки и webhook для production.

5.3. Webhook подписка (для PROD)

По документации подписки управляются через subscriptions (есть POST и GET).

Типовой серверный обработчик webhook (Express):

import express from "express";

const app = express();
app.use(express.json());

app.post("/max/webhook", async (req, res) => {
  const update = req.body; // Update из MAX
  // 1) определить пользователя/чат
  // 2) распознать команду или callback
  // 3) ответить сообщением или изменить подписки

app.listen(3000);

5.4. Загрузка файлов (PDF/PNG расписания)

MAX выдаёт URL для загрузки через POST /uploads и предупреждает о замене type=photo на type=image. 

export async function getUploadUrl(type = "image") {
  const res = await fetch(`${API}/uploads`, {
    method: "POST",
    headers: { Authorization: MAX_TOKEN, "Content-Type": "application/json" },
    body: JSON.stringify({ type })
  });
  if (!res.ok) throw new Error(await res.text());
  return res.json(); // содержит URL для последующей загрузки
}

6. Мини-приложение: код клиента и валидация InitData

6.1. Подключение MAX Bridge

В мини-приложение подключается библиотека:

<script src="https://st.max.ru/js/max-web-app.js"></script>
<script>
  const webApp = window.WebApp;
</script>

Это даёт доступ к объекту window.WebApp.

6.2. Валидация InitData

MAX передаёт стартовые параметры (Init Data), которые нужно валидировать, чтобы убедиться, что данные не подменены. Описание алгоритма включает:

  • URL-декодирование,
  • сбор key=value без hash,
  • сортировка,
  • формирование строки с \n,
  • вычисление secret_key = HMAC_SHA256("WebAppData", BotToken),
  • вычисление подписи hex(HMAC_SHA256(secret_key, data_check_string)) и сравнение с hash.

Пример серверной проверки (Node.js, псевдо-реализация):

import crypto from "crypto";

export function validateInitData(initDataRaw, botToken) {
  const decoded = decodeURIComponent(initDataRaw);
  const params = new URLSearchParams(decoded);

  const hash = params.get("hash");
  params.delete("hash");

  const pairs = [];
  for (const [k, v] of params.entries()) pairs.push(`${k}=${v}`);
  pairs.sort();

  const dataCheckString = pairs.join("\n");

  const secretKey = crypto
    .createHmac("sha256", "WebAppData")
    .update(botToken)
    .digest();

  const computed = crypto
    .createHmac("sha256", secretKey)
    .update(dataCheckString)
    .digest("hex");

  return computed === hash;
}

7. Выводы и оценка применимости MAX для расписания

  • MAX подходит как кросс-платформенный клиент: мини-приложение реализуется как web-интерфейс и может использоваться на мобильных устройствах и ПК при адаптивной вёрстке; в документации указаны ориентиры по экранам и отсутствие жёстких ограничений на браузеры.
  • Bot API закрывает ключевые сценарии: команды, уведомления, публикация расписания в чатах, закрепы, получение событий через webhook/long polling, отправка файлов.
  • Мини-приложение даёт лучший UX, но требует правильной валидации InitData и привязки пользователя к группе/профилю в вашей БД.
  • Для production нужно соблюдать рекомендации MAX: webhook вместо long polling и учитывать лимит запросов (30 rps).
