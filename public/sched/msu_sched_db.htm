msu_sched — описание схемы (для RAG)

msu_sched — БД приложения расписания. Она хранит расписание как результат планирования (серии и конкретные занятия). Первичные источники данных:

  • NewStud — учебные планы, наборы, подпланы, группы, студенты.
  • nagruzka — преподаватели и нагрузка.

Ключевая идея для RAG: кому ставить предмет определяется в NewStud, а msu_sched хранит выбранные группы и фактически созданные слоты занятий.

Схема БД

Файл: public/sched/db_msu_sched.png

1) Верхний уровень

Timetable

Заголовок расписания факультета на период.

PK Timetable.id
FK facultet_id -> Facultet.id
  • Период: academic_year, period_type, period_name, start_date, end_date
  • Идентификация плана: educplan_id (как правило ссылка на NewStud.Educ_Plan.PrK_Plan)

Связь: Timetable (1) -> (N) Series.

2) Серии и занятия

Series

Серия занятий: «предмет + тип занятия (+ преподаватель)» внутри Timetable.

PK Series.id
  • FK timetable_id -> Timetable.id
  • FK subject_id -> Subject.id
  • FK prepod_id -> Prepod.id
  • FK classType_id -> ClassType.id
  • Нагрузка серии: hoursLoad
  • Связь групп: Series (N) <-> (M) Group через v_Series_Group(series_id, group_id)
  • Занятия: Series (1) -> (N) Schedule

Schedule

Конкретное занятие (слот): дата/время/аудитория.

PK Schedule.id
  • FK series_id -> Series.id
  • FK prepod_id -> Prepod.id (можно переопределять относительно серии)
  • FK classType_id -> ClassType.id
  • FK room_id -> Room.id
  • FK paraNum -> ParaNum.id
  • Время: startDt, endDt

Правила конфликтов (обычно контроль приложением/констрейнтами):

  • один Room не может иметь пересекающиеся интервалы;
  • один Prepod не может вести пересекающиеся интервалы;
  • группы, привязанные к сериям, не должны пересекаться по времени.

3) Учебные сущности (часто кеш/проекция)

Facultet

Справочник факультетов приложения.

PK Facultet.id

Внешняя привязка: NFirm (обычно NewStud.Firm.NFirm)

Group

Группы, используемые при составлении расписания.

PK Group.id
FK facultet_id -> Facultet.id

Атрибуты: kurs, potok, studsCnt (численность как кеш)

Student

Если хранится детализация до студента.

PK Student.id
FK group_id -> Group.id

Subject

Дисциплины, доступные для расписания.

PK Subject.id
FK facultet_id -> Facultet.id

Атрибут: Semestr (если используется)

Prepod

Преподаватели.

PK Prepod.id

v_Prepod_Subject

Разрешённая/типовая связка «преподаватель–предмет».

  • prepod_id -> Prepod.id
  • subject_id -> Subject.id

4) Аудитории и вместимость

Campus -> Building -> Room

Иерархия мест проведения.

  • Building.campus_id -> Campus.id
  • Room.building_id -> Building.id
  • Room.facultet_id -> Facultet.id (владелец)

CapacityType, v_Room_Capacity

Вместимость аудитории по типам рассадки.

  • v_Room_Capacity(room_id, capacityType_id, seatsCnt, is_primary, is_deleted)

5) Схемы звонков

ParaNum

Номер пары (1..N).

BellSchema, v_BellSchema_ParaNum

Схема звонков (времена начала/конца пар), часто привязана к зданию.

  • BellSchema.building_id -> Building.id
  • v_BellSchema_ParaNum(bellSchema_id, paraNum_id, startTime, endTime)

6) Карта связей (кратко)

  • Facultet (1) -> (N) Timetable
  • Timetable (1) -> (N) Series
  • Series (1) -> (N) Schedule
  • Series (N) <-> (M) Group через v_Series_Group
  • Schedule (N) -> (1) Room -> Building -> Campus
  • Schedule (N) -> (1) Prepod
  • Schedule (N) -> (1) ClassType

7) Как это использовать совместно с NewStud

Для мастера создания серий:

  1. В NewStud получить предметы и нагрузку на выбранные Plan + Year_Study + Course + Semester (через Comp_Term).
  2. В NewStud определить группы/студентов, которые должны изучать предмет (учитывая FK_Sub_Plan, а также случаи FK_Sub_Plan IS NULL).
  3. Создать Timetable (если нет) и Series.
  4. Привязать группы к серии: v_Series_Group.
  5. Создать конкретные занятия: Schedule.
